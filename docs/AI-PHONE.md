# AI-phone accessibility bridge

The existing package remains `com.dosa42.codexgoal`; this update is fixed at version 0.1.20/code 20. The service component is `com.example.aiphone.AiPhoneAccessibilityService`. Existing terminal, workspace, console, executor and voice code is preserved. The new service does not start microphone capture.

Android must enable the accessibility service before it can run. It connects outward to the resident Termux broker at TCP 127.0.0.1:8793 using UTF-8 NDJSON. Android owns its lifecycle. Healthy sockets do not expire. EOF/write failure triggers reconnection, a new UUID epoch and full state. The service does not replay requests on reconnect.

`app/src/main/assets/ai-phone.schema.json` contains the coordinator's full wire schema, including public executor file contracts implemented by the broker rather than this service. Native discovery returns that exact object and the SHA256 of its original bytes. WireSchema evaluates the constraints used by this contract for incoming frames before dispatch and outgoing frames. Unknown methods/parameters, malformed actions and stale handles fail before mutation.

All-display window enumeration is available from API 30; earlier Android exposes default-display windows only and advertises that limitation. Accessible children are traversed iteratively without node, depth or text caps. Identity-based cycle detection prevents infinite traversal. Full text and Android action lists remain available. Unmapped Android action IDs are labelled `android_action_ID` with `available:false`; no fake semantic handler is provided. Inaccessible window roots are reported in `unavailable`. Canvas pixels are not invented as text.

Android accessibility/display callbacks trigger coalesced snapshots. Initial connection emits a full state; changes emit typed deltas with baseRevision, changed nodes/windows and removals. `observe` provides full content or an explicit summary plus exact-schema selectors. Epoch/revision/display/window/node scope is checked again against a fresh observation before mutation.

Node actions target actual Android node handles. Global `performGlobalAction` has no display parameter and is truthfully `untargeted`; nonzero display requests are rejected. Its success only means accepted. App launch explicitly uses Android ActivityOptions.launchDisplayId (API 26+) and reports requested_display, not verified placement. Action/launch receipts initially say observedOutcome=unverified; subsequent events and broker predicates must establish the actual outcome. Screenshot global actions, if exposed by Android, are system actions; there is no screenshot-content or gesture observation transport advertised.

The private app SQLite mutation journal preserves immutable request IDs across process restart. Identical completed requests return the recorded response; conflicting payloads fail. A dispatch without a durable response remains uncertain and is never automatically repeated. There is no journal expiry or silent dedupe eviction.

Build tooling for this PC task is isolated under ignored `.build-tools/`. Source `.build-tools/env.sh`, then run `gradle :app:testDebugUnitTest :app:assembleDebug --console=plain --no-daemon`. Signing requires the existing matching ignored debug.keystore; never generate a replacement for an in-place update. Tests include existing baseline tests, native request rejection, persisted mutation journal semantics and the coordinator's 22 valid/invalid schema fixtures. Unit/Robolectric tests are not proof of installed phone behavior: deployment and phone0 acceptance belong to the browser/coordinator, preserving DeX and enabled services.

## Native identity and availability repair

Handles are assigned by Android `AccessibilityNodeInfo.equals` identity (source-node ID and window ID), additionally scoped by display/window. Identity keys retain separate untouched native copies. The same live node keeps its handle across traversal reordering; removal retires the handle, and replacement/reappearance allocates a new monotonically unique handle within the connection epoch. The platform API cannot reveal a provider reusing exactly the same native identity between observations, so this is not an assertion of provider-internal object lifetime. Production action validation takes a fresh capture before resolving the supplied handle.

`unavailable` participates in revision change detection. Any change to that array emits an authoritative full state instead of a delta, both when a root becomes inaccessible and when it recovers. Ordinary node/window changes continue to use deltas with the existing unchanged schema. Focused Robolectric tests execute the real service capture/action paths with distinct equal-looking Android nodes, reordering/removal/replacement, and cache reconstruction across root loss/recovery; they are not installed-device acceptance.
